# 拆分为两个独立端 + 账号登录改造

## 背景与目标

现有 `label-auto-dashboard` 是三合一（数据看板 + 质检平台 + 作业平台），且内置了 owner/各账号密码用于自动登录。

本次要做：

1. **复制出 2 份新项目**，现有 `label-auto-dashboard` **保持不动**：
   - `label-auto-qc`：只保留**质检平台**。
   - `label-auto-anno`：只保留**作业平台**。
2. **清理掉所有内置账号**（owner 密码、`_QC_LOGIN` 账号、`账号.md`、自动登录接口、登录门槛）。
3. **先登录账号，再显示该账号下的项目**：
   - 打开后先显示登录框（邮箱 + 密码）。
   - 登录成功后，才显示该账号有权限的项目。
   - 质检端只显示 `is_qc` 的项目；作业端只显示 `is_assigned` 的项目。
4. **登录状态持久化**：刷新页面、重启服务都不掉，除非主动「退出登录」。

## 关键设计

### 认证模型（从「内置 owner + 切换他人」改为「本人登录」）

- 登录后，后端保存**当前用户自己的 token + 用户信息**。
- 所有上游请求都用**该用户自己的 token**（不再用 owner token）。
- 质检/作业的 uid 取自**登录用户本人**，不再需要「质检员/作业员」下拉切换——登录的就是谁，就用谁。
- token 持久化到本地文件 `token.json`（登录时写入、登出时删除、启动时读取），从而**重启服务不掉登录**；刷新页面靠 `/api/me` 判断登录态。

### 项目过滤（账号下的项目）

上游 `/api/projects` 用本人 token 访问时，返回**所有项目**，但每项带权限标记：
- qc 角色带 `is_qc`（是否该项目的质检员）。
- member 角色带 `is_assigned`（是否该项目的作业员）。

因此：
- 质检端 `qc_setup` 只返回 `is_qc == true` 的项目。
- 作业端 `anno_setup` 只返回 `is_assigned == true` 的项目。

### 前端

- 新增**登录页**（邮箱/密码 + 登录按钮），登录成功进入主界面；主界面顶栏加「退出登录」。
- 打开页面先请求 `/api/me`：已登录直接进主界面，未登录显示登录页。
- 移除「质检员/作业员」下拉（登录者本人就是操作者）。
- 移除跨平台链接（数据看板 / 另一平台的跳转），每个副本只保留自己的页面。

## 受影响文件（每个副本内）

| 文件 | 改动 |
|---|---|
| `dashboard.py` | 删内置账号、删 autologin、删登录门槛；加 token 持久化；`qc_setup`/`anno_setup` 按 `is_qc`/`is_assigned` 过滤；uid 改用登录用户 |
| 前端 js | 加登录/登出逻辑；`api()` 不带 uid（后端用登录者 uid）；删下拉逻辑 |
| 前端 html | 加登录框 + 退出按钮；删跨平台链接、删质检员/作业员下拉 |
| `账号.md` | 删除（不再内置账号） |
| `index.html` / 另一平台文件 | 删除（每个副本只留自己的平台） |

## 边界与异常

- 未登录访问任何数据接口 → 返回 `need_login`，前端弹登录。
- token 失效/过期 → 上游返回 401 → 前端退回登录页（提示重新登录）。
- 登录后没有可操作项目（无 `is_qc`/`is_assigned`）→ 提示「该账号暂无此权限的项目」。
- 退出登录 → 删除 `token.json` + 前端回登录页。
- 后端启动时读取 `token.json`，若文件存在则恢复登录态。

## 预期结果

- 两个独立可运行的副本：`label-auto-qc`（质检）、`label-auto-anno`（作业），各自双击启动、各自登录使用。
- 无任何内置账号密码；每人用自己账号登录，只看到自己权限内的项目。
- 登录状态刷新/重启都不掉，主动退出才失效。
